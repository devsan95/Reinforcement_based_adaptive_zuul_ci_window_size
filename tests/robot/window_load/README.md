# Robot Load Generation for RL/TCP Window Testing

This suite generates high-volume, mixed Gerrit/Zuul events for RL window-size and throughput comparisons on the local dockerized demo stack.

## What it does

- Submits a configurable number of changes (default `300`).
- Mixes multiple scenarios with configurable weights:
  - `burst`: rapid submissions in short bursts.
  - `trickle`: paced one-by-one submissions.
  - `patchset`: amend+push updates to existing changes (patchset updates).
  - `recheck`: posts `recheck` messages on previously created changes.
- Spreads traffic across configurable projects and branches.
- Optionally marks a share of changes as gate-targeted via review labels (`Workflow +1`, `Code-Review +2`).
- Records artifacts designed for correlation with RL audit and throughput graphs.

## Prerequisites

- Local tutorial/demo services are up (Gerrit and Zuul APIs reachable).
- Python and `robotframework` installed.
- Typical tutorial credentials and endpoints:
  - Gerrit: `http://localhost:8080`
  - Zuul: `http://localhost:19090`
  - Auth: `admin:secret`

If needed, bring up the stack from `doc/source/examples` first (for example with your existing `up-rl-app` flow).

## Run commands

From repo root:

```powershell
python -m robot `
  -d tests/robot/window_load/results/default `
  tests/robot/window_load/suites/window_size_load.robot
```

Customized run (count, pacing, mix, tenant/pipeline targets):

```powershell
python -m robot `
  -d tests/robot/window_load/results/run-300 `
  -v TOTAL_COUNT:300 `
  -v PACE_MS:120 `
  -v SCENARIO_MIX:burst=50,trickle=25,patchset=20,recheck=5 `
  -v PROJECTS:test1 `
  -v BRANCHES:master `
  -v TENANT:example-tenant `
  -v CHECK_PIPELINE:check `
  -v GATE_PIPELINE:gate `
  -v GATE_RATIO:0.40 `
  -v STATUS_SAMPLE_INTERVAL:20 `
  tests/robot/window_load/suites/window_size_load.robot
```

Dry-run/sanity check:

```powershell
python -m robot --dryrun tests/robot/window_load/suites/window_size_load.robot
```

## Outputs and artifacts

Robot output directory (`-d`) includes the standard Robot files:

- `log.html`
- `report.html`
- `output.xml`

The suite also writes workload artifacts under `${ARTIFACT_DIR}` (default `${OUTPUT DIR}/window-size-load`):

- `events.jsonl`: event-by-event stream (`new_change`, `patchset_update`, `recheck`) with timestamps, scenario, project/branch, change id.
- `status_samples.jsonl`: periodic status snapshots of selected pipelines and queue window fields (`window`, `rl_recommended_window`, queue depth).
- `summary.json`: top-level counts, scenario distribution, runtime, and artifact paths.

These files are intended for side-by-side analysis with:

- scheduler RL audit (`/var/lib/zuul/rl_window_audit.jsonl`)
- throughput/comparison reports generated by existing RL scripts.

## Caveats

- A `TOTAL_COUNT` near 300 can take significant time depending on local resources and queue/backlog behavior.
- `patchset` and `recheck` scenarios depend on prior created changes; the suite auto-seeds with new changes when needed.
- The suite is traffic generation only; it does not reconfigure Zuul or restart services, so existing demo flow remains unchanged.
